# 架构说明

> 由 `DEVELOPMENT.md` 拆分而来。主文件保留架构总览与问题索引，细节放这里。

## 一、为什么是「构建期渲染」

单文件 HTML 新闻页在普通浏览器里没问题，但在对话预览器里会连续踩三类墙：

| 墙 | 表现 | 影响 |
|---|---|---|
| 沙箱 iframe | `sandbox="allow-scripts"`，可能剥离内联脚本 | JS 渲染的列表变成空白 |
| CSP | `connect-src 'none'` 在网络层拦掉 `fetch`/XHR | 运行时同步、抓全文、公共代理全不通 |
| 导航限制 | `window.open` / `target="_blank"` 静默失败，无 `allow-top-navigation` | 「查看原文」点了没反应 |

另外 `file://` 的 origin 是 `null`，浏览器默认禁止跨域请求；`raw.githubusercontent.com` 以 `text/plain` + `nosniff` 返回，仓库里的 `.html` 点开只是源码。

**结论**：只有构建期就存在于 HTML 响应里的内容，才保证在预览器中可读。`<noscript>` 只能提示，不能凭空渲染数据。

## 二、四层结构

```
┌─ 数据层 ─────────────────────────────────────────────┐
│ feeds.json        6 个原有 RSS + 澎湃 7 条（可启停）      │
│ articles.csv      15 列唯一数据源（含 fetched_at）         │
│ links.csv         原文链接永久台账（只追加不清理）         │
│ snapshot.csv      2026-11-05 原始抓取记录（溯源）         │
└──────────────────────────────────────────────────────┘
                    ↓ 构建期（Python，不在浏览器里发生）
┌─ 构建层 ─────────────────────────────────────────────┐
│ build.py                                              │
│   ├─ 并发抓 RSS / 取标题与简介 / 去重合并                │
│   ├─ 写回 articles.csv（每次刷新落盘）                │
│   ├─ 新链接追加进 links.csv（只追加）                 │
│   ├─ prune_content()：正文超 7 天清空、链接全留       │
│   └─ 整份 CSV 内联进 zaker-news.html 的 INLINE_DATA 块   │
│ build_static.py                                       │
│   ├─ 生成 index.html（零脚本、默认深色）                  │
│   ├─ 预生成 CSS 状态机（radio + label + :has）            │
│   └─ 把同一份兜底 DOM/CSS 幂等注入交互版                 │
│ .github/workflows/update.yml  每 6 小时跑一次并 commit    │
└──────────────────────────────────────────────────────┘
                    ↓ 产物直接写入 HTML DOM
┌─ 表现层 ─────────────────────────────────────────────┐
│ index.html（51 KB）                                    │
│   ├─ 标题 + 简介 + 原文链接写进 DOM，快照折叠          │
│   ├─ 20 个隐藏 radio/checkbox + label                  │
│   ├─ 39 条 :has() 规则（频道/来源/字号/主题/紧凑/过滤）    │
│   └─ 零 <script>、零 fetch、零 localStorage             │
│ zaker-news.html（197 KB）                             │
│   ├─ 脚本可用 → 完整交互（同步/订阅/全文/搜索/收藏）       │
│   └─ 脚本被拦 → 读 #main 里的零脚本兜底 DOM              │
└──────────────────────────────────────────────────────┘
                    ↓ push 到 main
┌─ 发布层 ─────────────────────────────────────────────┐
│ GitHub Pages（Deploy from a branch / main / root）      │
│ 真实 HTTPS origin，解决 file:// 的 origin=null          │
└──────────────────────────────────────────────────────┘
```

## 三、关键设计决策

### 1. 数据单向流动

RSS → CSV → HTML，HTML 不回写 CSV。用户在页面里的收藏、主题、字号等状态只存本机 localStorage，不进入构建产物；静态版连这些状态都不存，用 CSS `:checked` 表达。

### 2. 双轨而非替换

最开始的交互版保留全部功能，另加一份零脚本静态版。交互版通过 `state.packMode = isOfflinePreview()` 判断环境：预览 / iframe / `file://` / blob / data 下不发起任何自动外网请求，直接读内联数据；真实浏览器或本地服务器下恢复同步与全文抓取。

### 3. 控件状态预生成

按钮本质是"运行时动作"，无法缓存。改用 `<input type="radio|checkbox">` + `<label>` + CSS `html:has(#id:checked) .art:not(.xxx){display:none}`：

- `label` 点击是浏览器原生行为，**禁用 JS 也生效**，CSP 管不着
- 不同 radio 组天然互不干扰，多个状态可同时保持
- `@supports not selector(:has(*))` 时隐藏控件、显示全部文章，内容不丢

### 4. 抓取失败不清空

`build.py` 的 `merge()` 按 `id` → 规范化标题 → `link` 三级匹配合并；新结果没有 `content` 时保留旧值**和旧的 `fetched_at`**（否则 TTL 会被虚假续期）；`link` 永不被空值覆盖。实测 13 个源全部 403 时，23 条数据前后完全一致。

### 4b. 链接永久、正文短期

| 字段 | 生命周期 | 落点 |
|---|---|---|
| `link` | 永久 | `articles.csv` + `links.csv` 追加台账 |
| 标题 / 摘要 / 来源 / 发布时间 / 频道 | 永久 | `articles.csv` |
| `content` | 7 天（按 `fetched_at`） | 过期清空，`tag` 改「快照·正文已过期」 |

页面端另有一层：https / localhost 下可绑定本地 `articles.csv`，同步完由 File System Access API 自动写回，把"数据跟浏览器走"改成"数据跟文件走"。沙箱与 `file://` 不支持，降级为导出。

### 5. 幂等构建

`build_static.py` 用 `STATIC_FALLBACK_CSS_START/END`、`STATIC_FALLBACK_START/END` 四个标记做幂等替换；重复执行体积不变。`build.py` 用 `INLINE_DATA_START/END` 标记重建内联 CSV 块。

## 四、验证矩阵

每次改动后至少覆盖：

| 环境 | 期望 |
|---|---|
| 禁用 JavaScript（393×852） | 23 篇文章可见、控件可点、多状态保持、默认深色 |
| `file://` 双击 + 禁用 JS | 同上 |
| `sandbox="allow-scripts"` iframe + Blob URL | 同上，零报错 |
| 真实浏览器 + 本地服务器 | 交互版 JS 接管，兜底 DOM 残留 0，主题按钮可切换 |
| `build.py --offline` 连跑两次 | 两份页面体积不变，内联 CSV 与 `articles.csv` 完全一致 |
| 联网抓取全部失败 | 数据条数与正文数不变 |
| `build.py --offline` 连跑两次 | CSV / links.csv 内容一致，正文不过期 |
| 造一条 8 天前的正文 | 正文清空、链接保留、未过期正文不受影响 |
| 导出 CSV 再导入 | 15 列往返一致，`fetched_at` / `link` 不丢 |
| 全部请求立即 403 时点同步 | ≤ 1 秒收敛，状态条显示已完成 x/y |
| 全部请求挂起时点同步 | ≤ 4 秒收敛，无后台残留 |
| 预览环境点同步 | ≤ 2.5 秒快速探测并明确提示 |
| 静态版禁用 JS 点标题 | `target=_blank` + `rel=noopener noreferrer` 直达原文 |
| 交互版点有链接的卡片 | 新开 1 个页面、阅读页不打开、零报错 |
| 预览沙箱 window.open 被拦 | 兜底菜单出现，含完整 URL 与复制/搜索选项 |
| 紧凑模式 | 简介与原文按钮仍可见，只收起折叠快照 |

## 五、仍然做不到的事

- **实时同步的预算**：交互版 `SYNC_BUDGET=4s` / `FEED_BUDGET=3.5s` / `CHANNEL_TIMEOUT=2.6s`，预览环境 `2.5s`；通道并行竞速、首个有效胜出、其余立即 abort，不用全局串行排队（详见 [问题记录 10](./问题记录/同步慢-全局串行节流拖垮快速失败.md)）
- **实时最新**：纯静态只能展示「最近一次构建时刻」的快照；要永远最新必须保留运行时服务或后端
- **宿主禁止跳出**：`window.open` / 外链被预览器拦时，无法在预览内打开第三方站点；交互版弹复制/搜索/本页阅读菜单，静态版用普通链接 + 明文 URL，无链接条目给搜索兜底
- **超长 `srcdoc` 属性注入**：把 60 KB+ HTML 拼进 HTML 属性会让浏览器崩；真实预览器用 Blob URL 注入（已验证）
- **付费墙 / 强反爬 / 客户端渲染站点**：正文提取会失败，页面如实标注「只提供摘要」
