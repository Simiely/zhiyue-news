# 使用指南

> 由 `README.md` 拆分而来：门面只留简介与快速开始，详细操作放这里。

## 一、三种打开方式

**① 直接看（零配置）**
双击 `index.html` 或在对话预览里打开。默认深色，23 条真实订阅、7 篇正文；频道 / 来源 / 字号 / 深浅色 / 紧凑 / 只看含正文都能点，不需要联网、服务器或账号，禁用 JavaScript 也生效。

`zaker-news.html` 同样可直接打开：脚本能跑时是完整交互版，脚本被剥离时自动降级为同一份离线内容 + 同一组可点控件。

**② 本机起服务，用完整交互版**
```bash
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/zaker-news.html
```
此时恢复联网同步、订阅管理、全文抓取、搜索、收藏、原文跳转。`window.open` 不再被沙箱拦截。

**③ GitHub Pages（真实 HTTPS 网址）**

仓库已带 `.github/workflows/update.yml` 与 `.nojekyll`，配置一次即可：

1. `Settings → Actions → General → Workflow permissions` 选 **Read and write permissions**（工作流要提交快照）
2. `Settings → Pages → Build and deployment → Source` 选 **Deploy from a branch**，分支 `main`，目录 `/ (root)`，保存
3. 打开 `https://<用户名>.github.io/<仓库名>/`
4. `Actions → 更新新闻快照 → Run workflow` 可立即重抓；之后每 6 小时自动跑

临时预览也可用第三方代理 `https://htmlpreview.github.io/?https://github.com/<用户>/<仓库>/blob/main/index.html`；它不是 GitHub 官方产品，脚本跑在 `allow-scripts` 沙箱里——本项目静态版本来就没有脚本，反而最适配。长期使用仍建议 Pages。

## 二、为什么有些按钮在预览里点不动

| | 按钮（运行时） | 缓存（构建期） |
|---|---|---|
| 发生时刻 | 打开页面后点击那一刻 | 构建脚本抓 RSS、生成 HTML 时 |
| 依赖 | `<script>` 执行、`fetch`、`window.open`、localStorage | 什么都不依赖，内容已在 HTML 响应里 |
| 预览沙箱里 | 脚本可能被剥离；CSP `connect-src 'none'` 拦掉请求；弹窗被静默禁止 | 浏览器只负责显示 |

**能缓存的是「数据」和「每一种交互的结果」，不能缓存「现场去拿数据」这个动作本身。** 因此：

- 频道 / 来源 / 字号 / 深浅色 / 紧凑 / 只看含正文 → 已用 `radio + label + :has()` 预生成，零 JS 可点
- 实时同步、抓原文正文 → 需要真实浏览器 + 网络，用交互版
- 宿主禁止跳出 → 「查看原文」是普通 `<a href>`，按钮上直接显示完整 URL，长按复制到浏览器打开；正文已在本页，不跳转也能读

## 三、更新数据

```bash
python3 build.py            # 联网重抓 → 更新 articles.csv → 重建两份页面
python3 build.py --offline  # 只改了 CSV，不联网，秒级重建
python3 build.py --fetch-only  # 只抓取更新 articles.csv，不改 HTML
python3 build_static.py     # 只重建两份页面（含预生成按钮状态），不联网
```

只用 Python 标准库。`build.py` 的抓取逻辑：

1. 并发拉取 `feeds.json` 里启用的 RSS/Atom，优先取 `content:encoded / content` 的原始 HTML 正文
2. 只有摘要时按 `link` 抓原文 HTML，用轻量正文提取（优先 `article` / `main` / 常见正文容器，抽 `<p>` 与 `<h2>`）
3. 按 id / 规范化标题 / 链接去重合并，**抓不到正文时保留上一版内容**
4. 写回 `articles.csv`，把整份 CSV 内联进 `zaker-news.html`，再调用 `build_static.py` 重建两份页面

网络受限或站点反爬时脚本会打印失败来源并保留上一版数据；实测 6 个源全部 403 时 23 条数据前后完全一致。

### 定时更新

工作流已配置 `cron: '17 */6 * * *'`（UTC，错峰避开源站限流）。自建 cron 也可：

```
0 */6 * * * cd <仓库目录> && python3 build.py >> build.log 2>&1
```

## 四、CSV 字段

```
id, channels, title, summary, source, author, published_at,
image, tag, views, likes, read_minutes, content, link
```

| 字段 | 说明 |
|---|---|
| `channels` | 多频道用 `\|` 分隔，如 `科技\|生活\|推荐` |
| `content` | 段落用 `\|` 分隔；**`# ` 开头渲染成小标题** |
| `tag` | `快照·全文` 时阅读页标注「离线数据包」并显示版权说明 |
| `link` | 为空时如实显示「该订阅源未提供原文链接」，**不编造** |

含逗号或引号的字段用标准 CSV 双引号包裹（脚本自动处理）。读文件请用 `utf-8-sig`，否则 BOM 会混进第一个表头字段名。

## 五、常见问题

**Q：预览里整页空白？**
A：打开 `index.html`（零脚本版）。`zaker-news.html` 也有兜底，但若宿主连 DOM 都重写了，静态版最稳。

**Q：按钮点了没反应？**
A：确认打开的是 `index.html`；若 `:has()` 不被支持，控件会自动隐藏并显示全部文章，内容不会丢。

**Q：改了 `articles.csv` 页面没变？**
A：跑 `python3 build.py --offline`。页面数据是构建期内联的，运行时不会重新读 CSV。

**Q：数据多久更新一次？**
A：Pages 由 Actions 每 6 小时重建一次；本地打开看到的是 2026-11-05 的快照，跑一次 `build.py` 才刷新。
