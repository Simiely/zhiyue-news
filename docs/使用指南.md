# 使用指南

> 由 `README.md` 拆分而来：门面只留简介与快速开始，详细操作放这里。

## 一、三种打开方式

**① 直接看（零配置）**
双击 `index.html` 或在对话预览里打开。默认深色，23 条真实订阅（标题 + 内文简介）；**点标题或蓝色按钮在新窗口打开原文**，频道 / 来源 / 字号 / 深浅色 / 紧凑 / 只看含正文都能点，不需要联网、服务器或账号，禁用 JavaScript 也生效。

`zaker-news.html` 同样可直接打开：脚本能跑时是完整交互版，脚本被剥离时自动降级为同一份离线内容 + 同一组可点控件。

**② 本机起服务，用完整交互版**
```bash
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/zaker-news.html
```
此时恢复联网同步、订阅管理、搜索、收藏、原文跳转，`window.open` 不再被沙箱拦截。默认点卡片即新窗口打开原文；想看折叠的本地快照可进站内阅读页。

**③ GitHub Pages（真实 HTTPS 网址）**

仓库已带 `.github/workflows/update.yml` 与 `.nojekyll`，配置一次即可：

1. `Settings → Actions → General → Workflow permissions` 选 **Read and write permissions**（工作流要提交快照）
2. `Settings → Pages → Build and deployment → Source` 选 **Deploy from a branch**，分支 `main`，目录 `/ (root)`，保存
3. 打开 `https://<用户名>.github.io/<仓库名>/`
4. `Actions → 更新新闻快照 → Run workflow` 可立即重抓；之后每 6 小时自动跑

临时预览也可用第三方代理 `https://htmlpreview.github.io/?https://github.com/<用户>/<仓库>/blob/main/index.html`；它不是 GitHub 官方产品，脚本跑在 `allow-scripts` 沙箱里——本项目静态版本来就没有脚本，反而最适配。长期使用仍建议 Pages。

## 二、为什么有些按钮在预览里点不动

| | 按钮（运行时） | 缓存（构建期） |
|---|---|---|
| 发生时刻 | 打开页面后点击那一刻 | 构建脚本抓 RSS、生成 HTML 时 |
| 依赖 | `<script>` 执行、`fetch`、`window.open`、localStorage | 什么都不依赖，内容已在 HTML 响应里 |
| 预览沙箱里 | 脚本可能被剥离；CSP `connect-src 'none'` 拦掉请求；弹窗被静默禁止 | 浏览器只负责显示 |

**能缓存的是「数据」和「每一种交互的结果」，不能缓存「现场去拿数据」这个动作本身。** 因此：

- 频道 / 来源 / 字号 / 深浅色 / 紧凑 / 只看含正文 → 已用 `radio + label + :has()` 预生成，零 JS 可点
- 实时同步、按需抓原文正文 → 需要真实浏览器 + 网络，用交互版（默认已关闭，`build.py --with-fulltext` 恢复）
- 宿主禁止跳出 → 静态版是普通 `<a href>` 且按钮印完整 URL，长按复制到浏览器打开；交互版会自动弹出复制链接 / 搜索 / 本页阅读菜单

## 三、更新数据

```bash
python3 build.py            # 联网重抓 → 落盘 CSV → 归档链接 → 7 天清理 → 重建两份页面
python3 build.py --offline  # 不联网，仍刷新落盘与重建（秒级）
python3 build.py --fetch-only  # 只抓取 + 落盘 + 清理，不重建 HTML
python3 build.py --prune-days 14   # 正文保留期改成 14 天
python3 build.py --no-prune        # 本次跳过正文清理
python3 build.py --with-fulltext   # 恢复按需抓原文正文（默认关闭）
python3 build_static.py     # 只重建两份页面（含预生成按钮状态），不联网
```

只用 Python 标准库。`build.py` 的抓取逻辑：

1. 并发拉取 `feeds.json` 里启用的 RSS/Atom，取标题、简介、发布时间与原文链接
2. **默认不再抓原文正文**（`MAX_ARTICLE_FETCH=0`）；RSS 自带的 `content:encoded` 保留为折叠的本地快照。加 `--with-fulltext` 才按 `link` 抓原文并做轻量正文提取
3. 按 id / 规范化标题 / 链接去重合并，**抓不到正文时保留上一版内容**
4. 写回 `articles.csv`（15 列），把新链接追加进 `links.csv`，按 `fetched_at` 清理超过 7 天的正文
5. 把整份 CSV 内联进 `zaker-news.html`，再调用 `build_static.py` 重建两份页面

网络受限或站点反爬时脚本会打印失败来源并保留上一版数据；实测 6 个源全部 403 时 23 条数据前后完全一致。

### 定时更新

工作流已配置 `cron: '17 */6 * * *'`（UTC，错峰避开源站限流）。自建 cron 也可：

```
0 */6 * * * cd <仓库目录> && python3 build.py >> build.log 2>&1
```

## 四、CSV 字段

```
id, channels, title, summary, source, author, published_at,
image, tag, views, likes, read_minutes, content, link, fetched_at
```

| 字段 | 说明 |
|---|---|
| `channels` | 多频道用 `\|` 分隔，如 `科技\|生活\|推荐` |
| `content` | 段落用 `\|` 分隔；**`# ` 开头渲染成小标题** |
| `tag` | `快照·全文` 时阅读页标注「离线数据包」；正文过期后为 `快照·正文已过期` |
| `link` | **永久字段**：为空时如实显示「该订阅源未提供原文链接」，不编造；有值时同步归档到 `links.csv` |
| `fetched_at` | 正文快照抓取时刻（`YYYY-MM-DDTHH:MM:SS`），7 天 TTL 的计时起点；沿用旧正文时保留旧值 |

含逗号或引号的字段用标准 CSV 双引号包裹（脚本自动处理）。读文件请用 `utf-8-sig`，否则 BOM 会混进第一个表头字段名。

### 链接台账与正文过期

`links.csv`（`id, title, source, link, first_seen`）**只追加、不清理**：即使某条正文过期被清空、或条目以后不再出现在列表里，原文链接仍留在台账里，随时可回溯。

`prune_content()` 在每次构建（含 `--offline`）都跑：

```
content 非空 且 (今天 − fetched_at) > 7 天
   → content = ""，tag = "快照·正文已过期"，fetched_at = ""
   → 保留 id / channels / title / summary / source / author / published_at / image / link
```

`fetched_at` 缺失但正文存在时，按构建当天补齐（旧版 14 列 CSV 平滑迁移）。`--prune-days` 改天数，`--no-prune` 跳过，`--prune-days 0` 等价于不清理。

### 订阅指定内容（澎湃新闻等）

`feeds.json` 里三种源：

| type | 必填 | 说明 |
|---|---|---|
| `rss` | `url` | 站点自带 feed，最稳 |
| `rsshub` | `route` | 按 `rsshub_instances` 顺序竞速，首个有效胜出 |
| `thepaper_hot` | `url` | 澎湃官方 JSON 热榜，解析 `hotNews` 并用 `contId` 拼原文链接 |

已内置澎湃：首页头条 `/thepaper/featured`、时事 `25950`、财经 `25951`、思想 `25952`、国际 `122908`、科技 `119908` + 官方热榜。加新栏目只需复制一条改 `route`。公共 RSSHub 实例可能被 Cloudflare 挑战拦（`rsshub.app` 在数据中心出口常见 403），所以配了多实例；长期用建议在自建实例里加自己的地址。

### 页面端自动落盘

在 `https://` 或 `http://localhost` 下打开 `zaker-news.html` → 「我的 → 数据 → 绑定本地 articles.csv」选一次文件，之后**每次同步 / 刷新自动写回**，数据跟文件走，换浏览器 / 清缓存也不丢。文件句柄存 IndexedDB，刷新后自动恢复；权限失效时会提示重新授权。预览沙箱、`file://`、不支持 File System Access API 的浏览器会明确提示改用「导出 CSV」。写回的是 15 列标准 CSV，可直接被 `build.py --offline` 读取。

## 五、常见问题

**Q：预览里整页空白？**
A：打开 `index.html`（零脚本版）。`zaker-news.html` 也有兜底，但若宿主连 DOM 都重写了，静态版最稳。

**Q：按钮点了没反应？**
A：确认打开的是 `index.html`；若 `:has()` 不被支持，控件会自动隐藏并显示全部文章，内容不会丢。

**Q：改了 `articles.csv` 页面没变？**
A：跑 `python3 build.py --offline`。页面数据是构建期内联的，运行时不会重新读 CSV（但会重新落盘 + 归档链接 + 清理过期正文）。

**Q：为什么 7 天后文章只剩摘要？**
A：正文快照按 `fetched_at` 超过 7 天自动清理，这是刻意的版权与体积策略；链接、标题、简介、来源都还在，点卡片即可直达原文。想保留更久用 `--prune-days 14`，想按文章发布时间计时告诉我改口径。

**Q：点卡片为什么不进阅读页了？**
A：v1.9.2 起默认「点卡片直接在新窗口打开原文」。想回站内阅读页：「我的 → 订阅更新 → 关掉『点卡片直接打开原文』」，或在预览环境被拦时从兜底菜单选「在本页阅读原文」。无原文链接的条目会进阅读页，并提供按标题搜索。

**Q：原文链接会丢吗？**
A：不会。`link` 永不被空值覆盖，且每条链接都追加进 `links.csv` 永久台账。

**Q：点「联网更新」转很久？**
A：预览 / 对话预览器 / `file://` 里注定连不出去，现在会在 **2.5 秒**内快速探测后明确提示「预览环境无法联网 · 离线数据包已就绪」，页面内容本来就在 HTML 里，不需要同步。真实浏览器下：请求秒失败约 0.6 秒收敛，全部挂起最多 3.5 秒；状态条会显示「已完成 x/y」。同步进行中再次点击会取消在途自动同步并立即接管，不会被「正在同步中」挡住。想秒开请用本地服务器 + 真实浏览器，或直接用零脚本的 `index.html`。

**Q：数据多久更新一次？**
A：Pages 由 Actions 每 6 小时重建一次；本地打开看到的是 2026-11-05 的快照，跑一次 `build.py` 才刷新。
