# 预览信息太少-分层展示与三档密度

**TL;DR**：卡片上只有一句 68 字摘要，正文全被折叠，所以"没东西看"。根因是构建脚本 `first[:68]` 硬截 + 交互版 `line-clamp:1` + 快照默认收起。改为「一句摘要 → 完整提要 → 正文预览前 3 段 → 条目信息网格 → 原文 → 折叠完整快照」，并提供零脚本三档密度。

## 问题

用户反馈「现在的预览信息太少了，可以显示更多吗」。上一轮把页面简化为「标题 + 内文简介 + 点卡片跳原文」后，卡片确实变得很单薄。

## 根因（三个截断叠加）

| # | 位置 | 行为 |
|---|---|---|
| ① | `build.py` | `summary = (first[:68] + "…")` —— **构建期就把摘要硬截到 68 字**；实测 `articles.csv` 23 条 summary 平均仅 32.4 字、最长 69 字 |
| ② | `zaker-news.html` CSS | `.nr-body p{line-clamp:1}`、`.hc-body p / .pick-body p{line-clamp:2}` —— 列表卡片只显示 1~2 行 |
| ③ | 两份页面 | 7 篇有正文的条目，正文全部塞进 `<details>` **默认收起**；16 篇只有短摘要且无正文 |

数据侧还有一层客观限制：`content` 只有 7 篇非空（8~14 段、最长 3210 字），`author` / `image` 全空、`views` / `likes` 全 0、`read_minutes` 多为 0。这些信息**不能编造**，只能如实展示"未提供"。

`normalizeItems()` 里另有 `summary.slice(0,120)`，对实时 RSS 也会二次截断。

## 解决

**① 数据层放宽截断**

- `build.py`：`first[:68]` → `first[:240]`；并从已有 `content` 首段回灌较长提要，当前 23 条中 5 条立刻变得更充实（不必重新联网抓取）。
- `normalizeItems()`：`slice(0,120)` → `slice(0,300)`。

**② 静态版信息分层（默认「详细」）**

`build_static.py` 的 `body_html()` 重写，一张卡片依次是：

1. **一句摘要** `.s-sum`（60 字，仅简洁档显示）
2. **内文提要** `.s-brief`（完整 summary，不截断）
3. **正文预览** `.s-preview`：从 `content` 取前 3 段（含小标题转 `<h3>`），显示「前 N 段 / 共 M 段」；无正文的如实写「该订阅源只提供摘要，未提供正文」
4. **条目信息网格** `.s-info`：来源 / 频道 / 发布时间 / 正文段数与字数 / 原文域名 / 标记，6 格；空值写「未提供」，不编造
5. **原文主按钮** `s-open-primary`（印完整 URL，`target=_blank rel=noopener noreferrer`）
6. **完整快照** `<details class="s-snap">` 折叠，避免单卡过长
7. 版权说明

**③ 零脚本三档密度**

新增 `cMore` checkbox（默认勾选），配合原有 `cCompact`，纯 CSS `:has()` 实现：

| 档位 | 控件 | 可见内容 | 实测可见文本 |
|---|---|---|---|
| 详细（默认） | `cMore` 勾 / `cCompact` 不勾 | 提要 + 预览 + 信息网格 + 快照折叠 | **10,292 字** |
| 标准 | 关 `cMore` | 提要 + 一句摘要 + 原文 | 5,343 字 |
| 简洁 | 勾 `cCompact` | 一句摘要 + 原文 | 3,385 字 |

关键规则：`html:has(#cMore:checked) .s-sum{display:none}`，紧凑档再强制 `display:block`。**主按钮三档都保留**，不会因为收起而失去出路。

**④ 交互版同步**

- `state.moreInfo`（默认 `true`，持久化 `zy_moreInfo`），`render()` 写 `html[data-more]`；CSS 放开 `line-clamp:unset`
- 新增 `previewHTML()`：卡片显示本地快照前 2 段（约 200 字）与「共 N 段」；`metaHTML()` 追加「N 段正文」
- 阅读页简介卡后追加**正文预览前 3 段** + 6 格条目信息，仍不自动抓全文、无 loading
- 设置面板新增「卡片显示详细预览」开关；静态版与交互版两份都生效

## 验证（393×852）

| 场景 | 结果 |
|---|---|
| 静态版禁用 JS · 详细档 | 23 卡 / 23 提要 / 23 预览 / 23 信息网格 / **138 格信息** / 7 折叠快照 / 23 原文或搜索按钮 / 10,292 字 |
| 点「详细预览」→ 标准 | 预览与信息网格 `display:none`，提要与一句摘要保留，5,343 字 |
| 再勾「紧凑」→ 简洁 | 提要隐藏，**原文按钮仍 `display:block`**，3,385 字 |
| 交互版真实浏览器 | `data-more=1`、19 张卡全部带预览、摘要 `line-clamp:none`、零报错 |
| 交互版阅读页 | 提要 + 预览 + 6 格信息 + 主按钮，**无 loading** |
| 关掉详细预览 | `data-more=0`、卡片预览归零 |
| 沙箱 Blob iframe | `packMode=true`、`moreInfo=true`、19 个预览、零报错 |
| 交互版禁用 JS | 兜底 DOM 23 卡 / 23 预览 / 23 信息网格 / 10,300 字 |

## 预防

- 「显示更多」不等于把旧折叠区默认展开就完事：要先查**构建期有没有把数据本身截掉**，否则展开的还是那 68 个字。
- 摘要截断放宽要同时改三处：构建脚本、运行时解析、CSS `line-clamp`，漏一处就还是看不到。
- 信息密度给三档而不是两档：用户要"更多"时默认详细，但仍要能一键回到轻量扫读；**主操作按钮任何档都不能被隐藏**。
- 元数据为空就写「未提供」，绝不填占位假数据；无正文条目写清"该源只提供摘要"。
- 零脚本页面的密度切换用 `checkbox + :has()`，注意多条规则的先后顺序（`display:block` 要放在 `display:none` 之后才能覆盖）。
