# 刷新不稳定-竞态与硬超时

**TL;DR**：16 秒外层超时一到主流程就结束，底层通道却还在串行跑并偷偷写入，造成"有时刷出来、状态自相矛盾"。

## 问题

订阅刷新时好时坏：首页报「订阅源暂不可达」，频道页却显示「正常」；再下拉一次会叠加十几个请求，新条目偶发出现。

## 根因

1. 外层用 `Promise.race` 做总超时，超时后主流程提前 `return`，但 5 个通道仍在串行执行（最长 45 秒）
2. 残留任务结束后继续写 `state.items` 却不触发 `render()`，数据与界面不一致
3. 下拉刷新在同步未结束时复位，重复触发产生竞态
4. 免费公共代理本身不稳（无 SLA、间歇 5xx、限流、部分已停用），6 个源同时打同一个代理几乎必被限流

## 解决

```js
// 整次同步只用 Promise.all 收敛，不用会提前返回的 race
const seq = ++syncSeq;
const root = new AbortController();
const hard = setTimeout(() => root.abort(), SYNC_BUDGET);
res = await Promise.all(enabled.map(one));
// 每个 one 内：if (seq !== syncSeq || root.signal.aborted) return stale
```

- 通道由串行改**并行竞速**：首个有效结果胜出，其余立即 `abort()`
- 单源 6.8 秒 / 单次 7.5 秒硬上限；陈旧结果靠同步序号丢弃
- 缓存上次成功内容，**失败不清空不白屏**，状态条写明「已保留上次内容 · 上次成功 HH:MM」
- 频道条只在内容变化时重建；同步中重复下拉直接提示；自动同步加随机错峰与切前台最小间隔

实测：慢网络 6.8 秒收敛，之后 2.2 秒无任何后台写入；竞速胜出后 1.5 秒内 0 个新增请求。

## 预防

- 涉及"总超时 + 多子任务"时，不要在外层 `race` 里提前返回，让 `Promise.all` 统一收敛
- 每个异步分支都要带序号或 `AbortSignal`，防止陈旧结果回写
- 失败路径必须明确"保留上次内容"，别让用户以为刷新成功
- 免费代理只当尽力而为的通道，页面要能固定单一通道
