# 按钮点击抓不到-运行时与构建期

**TL;DR**：按钮是"现在这一刻去执行"，缓存是"提前做完写进文件"；能缓存的是数据和每种交互的结果，不能缓存"现场去拿数据"这个动作。

## 问题

内容已经能看了，但用户发现「有些可以了，有些还是不行」，并问：点击网页上的按钮抓取不到，为什么你可以缓存？

## 根因

| | 按钮（运行时） | 缓存（构建期） |
|---|---|---|
| 发生时刻 | 打开页面后点击那一刻 | 构建脚本抓 RSS、生成 HTML 时 |
| 依赖 | `<script>` 执行、`fetch`、`window.open`、localStorage | 什么都不依赖，内容已在 HTML 响应里 |
| 预览沙箱里 | 脚本可能被剥离；`connect-src 'none'` 拦请求；弹窗被静默禁止 → 点了没反应 | 浏览器只负责显示 → 稳定可见 |

前几轮只把**内容**缓存了，「联网同步 / 搜索 / 频道切换 / 字号 / 主题」这些按钮仍要 JS 运行时执行，所以仍然失效。

## 解决

把剩下的按钮也做**结果预生成**：频道、来源、字号、深浅色、紧凑、只看含正文全部改成 `<input type="radio|checkbox">` + `<label>` + CSS `html:has(#id:checked)`。

```css
html:has(#ch1:checked) .art:not(.ch1){display:none}
html:has(#f21:checked){--rd-font:21px}
html:has(#tLight:checked){--bg:#F2F2F7;--card:#FFFFFF;...}
@supports not selector(:has(*)){.ctl{display:none}}  /* 显示全部，内容不丢 */
```

- `label` 点击是浏览器原生行为，**禁用 JavaScript 也生效**，CSP 管不着
- 不同 radio 组天然互不干扰，多个状态可同时保持
- 选中态用 `html:has(#id:checked) label[for=id]` 高亮

实测（**彻底禁用 JS**）：默认 23 篇 / 深色 / 17px → 点「科技」14 篇 → 点「大字」21px（频道没丢）→ 点「浅色」背景 `rgb(242,242,247)`（三态同时保持）；「只看含正文」4 篇；沙箱 iframe 点「生活」5 篇，零报错；`file://` 禁用 JS 点「大字」21px。

## 预防

- 先问「这个动作需要现场发请求吗？」需要 → 纯静态永远做不到，如实说明并提供真实浏览器路径
- 纯展示类状态优先用原生表单控件 + CSS，别动不动写 JS
- 给 `:has()` 加 `@supports` 退化：老环境显示全量内容，而不是空白
- 静态页把完整 URL 明文显示在链接按钮上，宿主禁止跳出时用户仍能复制
