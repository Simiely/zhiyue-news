# 同步慢-全局串行节流拖垮快速失败

**TL;DR**：为规避免费 API 限流做的「全局串行节流链」把每个源的失败判定排队到 7 秒；请求明明全部秒失败，整次同步也要等满硬超时。删链、缩预算、预览快速探测后，秒失败场景从 7.0 秒降到 0.64 秒。

## 问题

用户反馈「点击同步还是非常慢」。前一轮已经修过刷新竞态（并行竞速 + 硬超时 + 同步序号），但点击「联网更新」仍要等 7 秒才出提示。

## 根因

真实浏览器按 393×852 视口、三种网络场景实测（修复前）：

| 场景 | 启动自动同步 | 手动点同步 |
|---|---|---|
| 所有请求**立即 403** | 7103 ms | 7009 ms |
| 所有请求挂起 9 s | 8027 ms | 6814 ms |

「立即 403」还要 7 秒，说明不是网络慢，是有任务一直悬着不让 `Promise.all` 收敛。定位到：

```js
let _rjLast=0,_rjChain=Promise.resolve();
function rss2jsonThrottled(url,signal){
  const task=async()=>{
    const gap=Math.max(0,1200-(Date.now()-_rjLast));
    if(gap)await abortableWait(gap,signal);   // ← 全局最小间隔 1.2 s
    _rjLast=Date.now();
    return fetchWithTimeout(url,CHANNEL_TIMEOUT,signal);
  };
  _rjChain=_rjChain.catch(()=>{}).then(task);  // ← 全局串行链
  return _rjChain;
}
```

1. **7 个源全部往同一条全局链追加任务**，每个至少间隔 1.2 秒 → 排队约 8 秒；
2. `fetchFeed` 用 `Promise.any(tasks)`，只要有一个通道还 pending 就不会 reject。其它三个通道秒失败后，**rss2json 仍在排队** → 单源被拖到 5~7 秒；
3. 整次同步只能靠 `SYNC_BUDGET=7500` 的 `root.abort()` 收尾，于是「全部 403」也恰好等 7 秒；
4. 放大因素：页面加载立即 `syncAll(false)` 跑 7 秒，期间用户点同步被 `if(state.syncing) return` 直接拦下，只弹「正在同步中，请稍候…」，主观上更像卡死；
5. 预览 / `file://` 环境注定全失败，却同样跑满 7 秒；
6. 同步过程无任何进度反馈，7 秒里界面纹丝不动。

顺带发现 `abortableWait` 的 abort 监听没有清理，会随同步次数累积。

## 解决

**① 删掉全局串行链**，改为「延迟 600 ms + 独立短超时 + 可被 abort 立即取消」：

```js
function abortableDelay(ms,signal){
  return new Promise((resolve,reject)=>{
    const t=setTimeout(()=>{cleanup();resolve();},ms);
    const onAbort=()=>{cleanup();reject(new Error("已取消"));};
    function cleanup(){clearTimeout(t);if(signal)signal.removeEventListener("abort",onAbort);}
    if(signal)signal.addEventListener("abort",onAbort,{once:true});
  });
}
function rss2jsonDelayed(url,signal){
  return abortableDelay(600,signal).then(()=>fetchWithTimeout(url,CHANNEL_TIMEOUT,signal));
}
```

限流的后果只是该通道自己失败，`Promise.any` 有其它通道兜底；**排队阻塞整体收敛**的代价远大于限流收益。

**② 缩短预算**：`SYNC_BUDGET 7500→4000`、`FEED_BUDGET 6800→3500`、`CHANNEL_TIMEOUT 5200→2600`、`FULL_TIMEOUT 7000→4000`（打开文章同样受益）。

**③ 预览快速探测**：`packMode` 下用 `PREVIEW_SYNC_BUDGET=2500`，2.5 秒无结果即停，并明确提示「预览环境无法联网 · 离线数据包已就绪，无需同步」。

**④ 手动点击接管而非干等**：`syncAll(manual)` 在 `state.syncing` 时若 `manual=true`，先 `activeSyncCtl.abort()` 取消在途自动同步，再 `++syncSeq` 让旧结果作废，由手动任务立即接管。启动自动同步延后 1.2 秒，先把内容渲染出来。

**⑤ 进度反馈**：`state.syncDone` 计数 + `updateSyncBar()` 只改状态条文字（不整页 `render()`，避免渲染本身成为卡顿源），显示「已完成 3/7」。

**⑥ 顺手修回归**：`updatesSection()` 调用了未定义的 `unreadItems()`，同步真的拿到新内容时整页渲染会抛 `ReferenceError`；补上 `function unreadItems(){return state.items.filter(o=>state.unread.has(o.id));}`。

## 验证（同口径重测）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 全部立即 403 · 手动同步 | 7009 ms | **638 ms** |
| 全部挂起 9 s · 手动同步 | 6814 ms | **3227 ms** |
| 直连成功 · 手动同步 | 78 ms | 112 ms（无回退） |
| 预览模式点同步 | ~7500 ms | **824 ms** |
| 自动同步进行中手动接管 | 被拦下返回 0 | 3230 ms 内出结果 |

四环境回归：静态版禁用 JS 23 篇 / 频道可点；交互版禁用 JS 23 篇 / 20 控件 / 深色；沙箱 Blob iframe `packMode=true` 零报错；真实浏览器 15 列 CSV 往返一致、绑定按钮在、同步 `syncDone=7`、固定 rss2json 通道仍可切。

## 预防

- 为限流加「全局排队」前，先算最坏排队时长，并确认**排队不会阻塞外层收敛**；用 `Promise.any` 时尤其危险。
- 任何排队等待都必须可 abort，且等待本身要有上限。
- 「快速失败」要真的快：所有通道明确失败（403 / 网络错）时应立刻收敛，不该等满硬超时。
- 启动即跑的后台任务要么延后，要么允许手动操作取消接管，别用一句「正在同步中」把用户挡在外面。
- 长时间操作必须有进度反馈；进度更新只改局部 DOM，别整页重渲染。
- 改完用「秒失败 / 全挂起 / 首通道成功」三种网络场景量墙钟时间，别只看功能对不对。
