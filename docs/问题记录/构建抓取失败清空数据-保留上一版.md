# 构建抓取失败清空数据-保留上一版

**TL;DR**：定时任务若把抓取结果直接覆盖 CSV，网络一抖动就会把已有正文全部清空；必须先与上一版合并。

## 问题

受限网络下 6 个源全部返回 403，如果 `build.py` 直接 `write_csv(rows)`，`articles.csv` 会变成空表，页面随后重建也会白掉。GitHub Actions 每 6 小时跑一次，等于把故障扩散到线上 Pages。

## 根因

1. 抓取脚本把"本次结果"当成"全部真相"，没有读取已有 CSV
2. 免费 RSS 源常对 CI IP 限流 / 403；站点改版、反爬、临时宕机都会导致单轮 0 条
3. 工作流没有失败保护，抓取失败仍会提交空数据

## 解决

`build.py` 增加三级匹配合并与正文保留：

```python
def merge(prev, fresh):
    by_id = {r["id"]: dict(r) for r in prev}
    by_title = {norm_title(r["title"]): r["id"] for r in prev}
    by_link = {r["link"]: r["id"] for r in prev if r.get("link")}
    for r in fresh:
        rid = r["id"] if r["id"] in by_id else \
              by_title.get(norm_title(r["title"])) or by_link.get(r["link"], r["id"])
        merged = dict(by_id.get(rid, {}))
        merged.update({k: v for k, v in r.items() if v not in ("", None)})
        if not merged.get("content") and by_id.get(rid, {}).get("content"):
            merged["content"] = by_id[rid]["content"]   # 抓不到正文 → 保留旧值
            merged["tag"] = by_id[rid].get("tag", "快照")
        by_id[rid] = merged
    return list(by_id.values())
```

工作流也加保护：

```yaml
- run: |
    python3 build.py --fetch-only || echo "::warning::部分订阅源抓取失败，沿用上一版数据"
    python3 build.py --offline
    python3 build_static.py
- run: |
    git add articles.csv index.html zaker-news.html
    if git diff --cached --quiet; then echo "没有新内容，跳过提交"; else git commit ...; git push; fi
```

实测：6 个源全 403 时打印每个失败来源，23 条数据 / 7 篇正文前后完全一致。

## 预防

- 定时构建任务一律"读旧 → 合并 → 写"，不要 blind overwrite
- 抓取失败要**逐源打印原因**，便于判断是限流还是源失效
- 没有 diff 就跳过 commit，避免无意义的历史与误触发 Pages
- 正文、链接这类"抓一次才有"的字段要单独做保留逻辑，别被空值覆盖
