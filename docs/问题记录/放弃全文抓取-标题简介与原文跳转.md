# 放弃全文抓取-标题简介与原文跳转

**TL;DR**：全文抓取链路（Jina Reader / 公共代理 / Readability）在中文媒体上命中率低、还拖慢打开速度；用户明确表示「抓取不到也没关系」。改为**数据只保留标题 + 内文简介，点卡片直接在新窗口打开原文**，本地正文快照降级为折叠的可选项。

## 问题

用户原话：「我突然觉得抓取不到也没关系，可以改成抓取标题和抓取内文简介，然后点击以后自动弹出新的网页，打开这个原文链接吗」。

此前几轮为了"在站内读全文"堆了很重的链路：

- RSS `content:encoded` 优先 → 不够长就按需抓原文
- 4 通道并行竞速（Jina Reader、其代理版、AllOrigins、CORSProxy）
- 轻量 Readability 提正文、缓存、失败 5 分钟退避、粘贴全文、字号、进度条

结果是：中文媒体多数只给摘要或只对登录/客户端渲染开放，抓取成功率低；每次打开文章还可能等 4 秒 loading；`RSS2JSON` 限流、公共代理 520/522 又让链路更脆。用户真正想要的其实只是**看到标题和简介，然后去原站看**。

## 根因

1. **目标错配**：把「站内读完」当成目标，但摘要-only 的源本来就更适合做"索引 + 跳转"，全文抓取是在补一个上游不愿提供的能力。
2. **预览沙箱硬约束**：`sandbox` 不带 `allow-popups` 时 `window.open` / `target="_blank"` 静默失败；不带 `allow-top-navigation` 时顶层跳转也被禁。直接改成"点就跳"会在预览里再次变成"点了没反应"。
3. **零脚本静态版**不能检测弹窗拦截，必须把 URL 明文印在按钮上供长按复制。
4. 16 条历史快照没有原文链接，若不做兜底，这些条目点击后毫无反应。

## 解决

**① 数据层只留标题 + 简介**

- `build.py` 把 `MAX_ARTICLE_FETCH` 默认设为 **0**：不再主动抓原文正文（最不稳的一段链路）。RSS 自带的 `content:encoded` 仍保留为「本地快照」，但页面默认折叠、不主推。想恢复用 `--with-fulltext`。
- 页面不再自动触发 `loadFullText()`，`state.autoFull` 默认 `false`，阅读页不再出现 4 秒 loading 卡片。

**② 点击直接新开原文**

交互版新增 `state.openMode`（默认 `link`，持久化 `zy_openMode`）与 `handleOpen(id)`：

```js
function handleOpen(id){
  const o=state.items.find(x=>x.id===id); if(!o)return;
  const u=normLink(o.link||"");
  if(state.openMode==="link"&&u){
    if(state.unread.has(id)){state.unread.delete(id);persistSync();render();}
    state.current=id; state.pendingLink=u; state.lastAttempt=u;
    openExternal(u);          // window.open(u,"_blank","noopener,noreferrer")
    return;
  }
  openReader(id);             // 无链接 / 用户切回阅读页模式
}
```

`openExternal` 检测拦截：被拦时弹 `originBlocked` Action Sheet，给出**复制链接 / 按标题搜索 / 本页加载原文 / 再试新窗口**，并把完整 URL 明文显示。

**③ 阅读页降级为「标题 + 简介 + 原文入口」**

`readerBodyHTML` 重写：简介卡（含原文域名）、醒目蓝色主按钮「↗ 在新窗口打开原文」（按钮内直接显示完整 URL）、`⋯` 兜底菜单；已有正文快照放进 `<details class="rd-snapshot">` 默认收起，标注「非逐字全文」。版权说明与「继续阅读」保留。

**④ 零脚本静态版同样可点**

`build_static.py`：标题包成 `<a class="s-title-link" href="原文" target="_blank" rel="noopener noreferrer">`，卡片内加蓝色 `<a class="s-open-primary">` 按钮（印完整 URL），正文快照折叠进 `<details class="s-snap">`。紧凑模式改为只收起快照 / 说明，**不隐藏简介与原文按钮**。

**⑤ 无链接条目的兜底**

不编造原文链接，改为生成「⌕ 按标题搜索原文」的 Bing 搜索链接（`target="_blank"`，零脚本可点），并明确写「该订阅源未提供原文链接，同步成功后会自动补齐」。这样 23 条卡片**每条都有可点的出路**，不会出现点了没反应。

**⑥ 可回退**：设置里新增「点卡片直接打开原文」开关（默认开）；关掉后恢复原来的站内阅读页，本地快照、字体、收藏、分享都还在。

## 验证（393×852 真实浏览器）

| 场景 | 结果 |
|---|---|
| 静态版禁用 JS | 标题链接 `href=https://sspai.com/post/117827`、`target=_blank`、`rel=noopener noreferrer`；23 个原文/搜索按钮、7 个折叠快照 |
| 交互版点有链接的卡片 | 新开 1 个页面、URL 正确；**阅读页不打开**、零报错 |
| 切回 `reader` 模式 | 阅读页显示简介卡 + 主按钮 + 折叠快照，**无 loading**（不自动抓全文） |
| 预览沙箱 Blob iframe | `window.open` 被拦 → 兜底菜单出现，含「浏览器阻止了新窗口」与完整 URL |
| 交互版禁用 JS | 兜底 DOM 7 个标题链接 + 23 个按钮 |
| 紧凑模式 | 主按钮 `display:block`，不被隐藏 |

数据覆盖：`articles.csv` 23 条**全部有简介**、7 条带原文链接、7 篇本地快照；无链接的 16 条走搜索兜底。

## 预防

- 摘要-only 的源默认做「索引 + 跳转」，不要默认做「站内全文」；全文抓取应是用户显式触发的可选增强。
- 任何「点了跳出去」的设计，都要先问：**宿主允许 popup 吗？** 不允许就必须提供复制链接 / 搜索 / 本页阅读三条兜底，且把 URL 明文印出来。
- 零脚本页面无法检测弹窗拦截，只能靠明文 URL + 普通 `<a href>`；`target="_blank"` 必须配 `rel="noopener noreferrer"`。
- 折叠区只放"可选补充"，别把主操作按钮塞进会被紧凑模式隐藏的容器。
- 没有链接的条目不要留白，给搜索兜底，但**绝不编造原文 URL**。
- 产品方向简化时，保留旧能力作为可回退开关，比直接删干净更稳。
