# 查看原文无反应-弹窗拦截与链接解析

**TL;DR**：文章链接本身是好的，坏在「怎么打开」和「数据里有没有链接」——沙箱静默拦弹窗 + `guid` 冒充 URL + 快照缺链接。

## 问题

点「查看原文」完全没反应；部分条目压根没有按钮。实测 `https://sspai.com/post/117827` 本身可正常访问。

## 根因

1. `<a target="_blank">` 在 `sandbox` iframe（无 `allow-popups`）里静默失败：0 个新窗口、0 个提示
2. 自动抓全文期间整个页脚被 loading 卡片替换，按钮短暂消失
3. 23 条快照里 16 条没存 `link`，这些条目没有按钮
4. `guid` 非 URL 时被当成原文地址（如 `tag:example.com,2026:42`），相对链接 `/post/xxx` 没补全，点开必然 404
5. 第三方站普遍发 `X-Frame-Options` / `frame-ancestors`，页面内嵌原文也不可行

## 解决

- 统一走 `window.open` 并检测拦截；被拦时弹出菜单给出**在新窗口打开 / 在本页阅读原文 / 复制原文链接 / 按标题搜索**四条替代路径，不再静默失败
- 按钮旁加 `⋯`，任何环境都能主动打开菜单
- 抓全文期间**保留页脚**，原文入口始终可点
- 链接规范化：解码 `&amp;`、相对地址按订阅源补全、拒绝 `javascript:` 等非 HTTP 协议、`guid` 只有确实是 URL 才回退
- 同步时按标题归一化合并，实时 RSS 的真实链接补回快照条目且不产生重复
- 静态版改为普通 `<a href>`，并在按钮上**明文显示完整 URL**，宿主禁止跳出时可长按复制

## 预防

- 任何"打开外部"的动作都要有**被拦后的可操作兜底**，别只写 `target="_blank"`
- 链接字段必须规范化 + 校验协议；`guid` 不等于 URL
- 无链接条目给明确空态，不能假装能点
- 正文尽量内嵌，别把阅读体验押在"能跳出沙箱"上
